# AngelaNexus 产品体验与工程质量基线

## 产品定位

AngelaNexus 必须表现为“智能代理平台”，而不是要求用户理解内核、协议、路由语法和操作系统网络细节的配置工具。

核心目标按以下顺序实现：

1. 数据安全与隐私边界清晰；
2. 连接与运行稳定；
3. 智能化降低用户操作成本；
4. 高效率；
5. 低 CPU、内存、电量与网络额外开销；
6. 全平台一致的用户概念与能力；
7. 高级能力可进入，但不阻塞普通用户。

## 傻瓜式操作模型

首次使用原则上只需要：导入订阅、配置文件或节点 → 自动识别输入 → 自动识别可用运行时 → 自动配置校验 → 展示安全状态与关键风险 → 用户确认后启动。

日常使用围绕一个主要动作组织：当前连接状态、一键启动/停止、当前有效策略、网络与安全状态、简洁流量信息；异常时给出可执行的修复入口。高级设置采用渐进式展开。

## 智能化原则

智能行为必须可解释、可撤销、可验证。允许自动完成格式识别、运行时绑定、配置校验、重复节点去重、有效地区/策略组发现、平台能力检测、网络环境检测、故障诊断、安全检查和可安全执行的恢复动作。

涉及用户策略、节点数量、路由覆盖、账号数据删除或破坏性恢复时，不得替用户做不可逆决定。每个自动动作至少具备当前状态、动作原因、动作结果、撤销/恢复入口以及明确失败原因。

## 安全与隐私

默认采用最小数据原则。设备密钥、系统凭据、安全存储内容、本地敏感日志和未经用户确认的敏感配置字段不得默认上传。

普通配置可以跨平台同步；设备秘密必须留在平台安全存储中。订阅 URL、节点密码、token 等敏感字段必须按数据分类处理。

安全策略覆盖 DNS、IPv4/IPv6、代理未启动时的意外直连、TUN/VPN 状态异常、网络切换、运行时崩溃、配置加载失败、DNS 回退和不安全路由回退。安全策略失败时进入明确的安全失败状态，不悄悄降级为直连。

## 稳定性

运行时采用明确状态机：Idle → Preparing → Validating → Starting → Running → Degraded → Recovering → Stopped/Failed。

禁止 UI 自己推断运行状态。每个平台必须具备启动前配置验证、运行时健康检查、异常检测、有限次数恢复、恢复失败后的安全停止、崩溃后资源清理、网络切换处理和日志脱敏。恢复机制不得通过无限重启制造资源消耗。

## 高效率与低耗能

默认采用事件驱动而非高频轮询。状态使用共享事件流；诊断采样按需开启；空闲时降低后台活动；故障重试采用退避。

大型配置采用流式读取，避免重复保存原始配置副本；节点/规则使用受控缓存；日志限制大小；页面离开后释放不需要的重型资源。

移动端后台运行遵循系统生命周期；非必要任务不保持唤醒；流量统计与健康检查采用低频或事件触发；网络切换只执行必要的重新验证。

## 全平台体验

支持 Android、iOS、Windows、macOS、Linux。

所有平台共享用户概念、配置导入模型、代理/链路模型、路由策略模型、安全策略模型、运行状态模型和诊断模型。

平台只负责系统特有能力：VPN/TUN、系统代理、后台生命周期、权限、安全存储、网络接口、系统托盘/菜单栏、文件系统、系统级路由/防火墙。

## UI 方向

整体体验采用现代、简洁、卡片化、自适应布局。目标包括信息密度适中、首页突出连接状态、关键状态卡片化、手机底部导航、桌面导航栏/侧边栏、深色/浅色主题、动态字体与无障碍、桌面快捷键以及系统托盘/菜单栏。

视觉和交互只吸收目标产品的可用性经验，不复制其实现、资源或品牌元素。

## 页面层级

### 首页
回答：我现在是否安全运行？是否已连接？当前使用什么策略？网络是否正常？是否存在需要处理的问题？

### 配置
支持订阅链接、本地文件、单节点、多节点和混合格式；用户无需预先选择运行时。

### 代理
统一展示节点、策略组、自动选择、链式路径、延迟/健康状态和当前有效出口。

### 规则
按用户意图展示网络路由、防泄露、中国网络优化、服务/AI、GFW 状态与策略以及用户自定义覆盖。

### 设置
集中安全、数据与隐私、账户与同步、备份恢复、外观、平台、运行时和诊断。

## 成功标准

AngelaNexus 的“智能”以任务完成成本、错误率、资源消耗和可恢复性衡量，而不是按钮数量。

主要功能最终通过操作步骤数、首次成功率、配置识别成功率、启动成功率、异常恢复成功率、崩溃率、CPU、内存、移动端电量影响、网络额外开销和数据泄露测试结果验证。

任何“智能优化”在没有测试证据前不得标记为已验证。
