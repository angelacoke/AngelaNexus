# AngelaNexus 纲领之基

**项目：AngelaNexus**  
**定位：智能网络代理平台**  
**地位：项目最高级根本原则（Foundation / Immutable Principle）**

## 一、纲领之基

AngelaNexus 的开发、维护、重构、扩展、平台迁移、技术替换与版本迭代，必须始终继承项目最初确立的根本初衷。

实现可以演进，技术可以更替，架构可以优化，开发者可以更换；**项目初衷与本纲领之基不得因此被改变。**

## 二、不可逾越原则

除非世界互联网真正实现用户对网络连接、信息访问与网络路径的选择自由，否则本纲领之基持续有效，并不得被任何个人、团队、维护者、贡献者、开发者、技术方案、商业安排或版本迭代以任何理由削弱、绕过、篡改或废止。

任何后续工作都必须满足：

- 不以局部功能目标否定项目根本初衷；
- 不以技术便利替代或削弱用户选择自由；
- 不以开发者个人判断重新定义项目存在的根本理由；
- 不因平台、内核、供应商或技术栈变化而形成新的项目根本依赖；
- 不把实现层面的妥协升级为根本原则的改变。

## 三、允许变化与禁止变化

**允许变化：**

- 代码实现；
- 模块结构；
- 技术栈；
- 平台适配方式；
- 执行后端；
- 协议与传输实现；
- UI 与交互；
- 性能优化方案；
- 测试方法；
- 工程流程。

**禁止变化：**

- 项目根本初衷；
- 用户选择自由这一根本目标；
- 本纲领作为项目最高级约束的地位；
- 以任何低层级实现理由绕过本纲领。

## 四、继承规则

未来任何接手 AngelaNexus 的开发者，都应先阅读本文件，再阅读《AngelaNexus 底层宪级纲领》。

当具体实现与本纲领冲突时：

```
纲领之基
    ↓
宪级纲领
    ↓
架构原则
    ↓
工程实现
```

必须修正较低层级实现，而不得反向修改本纲领以适应实现。

## 五、变更门槛

本文件不是普通技术文档，不得通过普通功能开发流程修改。

任何拟议变更必须同时：

1. 明确证明其不改变项目根本初衷；
2. 证明其不削弱用户选择自由这一根本目标；
3. 取得项目最高治理主体的明确、可追溯授权；
4. 经过独立审查与项目完整性检查；
5. 在项目治理记录中留下永久可追溯记录。

在上述条件未全部满足前，本文件保持原状。

> **一句话原则：技术可以世代更替，开发者可以不断更换，但 AngelaNexus 为什么存在，不由后来者重新决定。**
